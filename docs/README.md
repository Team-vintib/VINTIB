# 문서 지도

이 레포는 모노레포다. BE·FE·AI·인프라가 같이 보는 문서와 파트 사이의 요청·응답을 **레포 안에 둬서, pull 한 번이면 모두가 같은 기준을 본다.**

## 기준 우선순위

1. **레포 문서가 노션보다 우선한다.** `docs/references/`에 사본이 있는 문서는 노션 원본과 달라도 레포를 따른다.
2. 노션이 레포 사본보다 새로워 보이면(최종 편집일 비교) 사용자에게 알리고, 사본 갱신은 묻고 나서 한다.
3. 레포에 없는 것만 노션이 기준이다. 노션 홈: [공통 PJT](https://dynamic-avenue-c3a.notion.site/PJT-396ae979d3a780c8af04f3fb7776b390).
4. 근거로 인용할 때는 레포 문서는 경로(필요하면 커밋 해시), 노션은 최종 편집일을 같이 적는다.

## 어디에 무엇이 있나

| 폴더 | 무엇 | 누가 고치나 |
| --- | --- | --- |
| [`references/`](references/README.md) | **모두가 같이 보는 기준 자료** 색인. 기능 정의서, API 명세, 카테고리 체계, ERD 등. 노션 사본은 이 폴더에 둔다 | 사본 갱신은 사용자 승인 후 |
| [`requests/`](requests/README.md) | **파트 간 요청과 응답.** 다른 파트(또는 사용자)의 결정·변경이 필요할 때 문서로 남기고, 받는 쪽이 같은 문서에 답한다 | 요청자가 쓰고 받는 쪽이 답한다 |
| `plans/` | 팀 시절(2026-07~08) 설계 계획. 설계 판단의 근거로 인용한다. **고치지 않는다** | — |
| `design/` | 팀 시절 디자인 스펙. FE 기준 문서 | — |
| `APIs.md`, `category-taxonomy.md` | 팀 시절부터 쓰던 기준 문서. 코드 주석이 이 경로를 가리켜 **위치를 옮기지 않는다.** 색인은 `references/README.md` | API 계약이 바뀔 때만 |
| `commit-convention.md` | 팀 시절 커밋 규칙(Jira 키). 이 레포의 커밋 규칙은 루트 `CLAUDE.md` Git 절이 대신한다 | — |

파트별 문서는 각 파트 폴더에 있다: `BE/docs/`(DB), `FE/docs/`(화면·컴포넌트·노션 FE 규칙 사본), `AI/docs/`(AI 게이트웨이·모델·워커). 서버·배포 문서는 `infra/docs/`.

## pull 하면 바로 보이게

레포를 받은 뒤 한 번 실행한다.

```bash
bash setup.sh
```

그러면 `git pull`(merge·rebase 모두) 직후에 **이번 pull로 새로 생기거나 바뀐 요청 문서**와 열린 요청 수가 터미널에 나온다(`.githooks/post-merge`, `post-rewrite`). 에이전트는 세션을 시작할 때 `requests/README.md`의 열린 요청을 확인한다(루트 `CLAUDE.md`).
