# 요청과 응답

다른 파트의 변경이나 결정이 필요할 때 이 폴더에 문서로 남기고, **받는 쪽이 같은 문서에 답한다.** 요청·응답·반영이 한 파일에 남기 때문에 pull 하면 무엇이 오갔는지 바로 보인다.

팀 시절과 달리 **처리한 문서를 지우지 않는다.** 상태만 바꾼다. 무엇을 왜 그렇게 정했는지가 이 레포의 기록이 된다.

## 언제 쓰나

- 다른 파트 코드의 변경이 필요할 때 — 직접 고치지 않고 요청으로 남긴다(루트 `CLAUDE.md` 파트 사이 규칙).
- API 계약(경로·필드·STOMP destination·ErrorCode·시각 형식)을 바꿔야만 하는 개선을 발견했을 때.
- 사용자(레포 주인)의 결정이 필요한데 채팅으로 끝내면 기록이 남지 않는 것 — 받는 쪽을 `owner`로 쓴다.
- 파트별로 에이전트 세션을 나눠 일할 때, 다른 파트 세션에 넘길 일.

## 파일

- 위치: 이 폴더 바로 아래. `YYYY-MM-DD-<요청쪽>-<받는쪽>-<slug>.md`
- `<요청쪽>`·`<받는쪽>`: 파트 코드 `be` `infra` `fe` `ai` `owner`(사용자). 팀원에게 보낼 때는 이름 로마자(예: `seoyun`).
- `<slug>`: 영문 소문자 kebab-case 2~4단어. 예: `2026-11-03-be-fe-bid-error-code.md`
- 형식은 [`_template.md`](_template.md). 머리의 `- 상태:` 줄이 이 문서의 상태 원본이다(pull 알림 훅이 이 줄을 읽는다).

## 상태

| 상태 | 뜻 | 바꾸는 사람 |
| --- | --- | --- |
| `요청` | 답을 기다린다 | 요청쪽(작성 시) |
| `답변` | 받는 쪽이 "응답" 절을 채웠다. 아직 반영 전 | 받는 쪽 |
| `반영` | 결정대로 바꿨다. "응답" 절에 커밋·PR이 있다 | 반영한 쪽 |
| `보류` | 지금은 하지 않는다. 이유와 다시 볼 시점을 적는다 | 받는 쪽 |
| `거절` | 하지 않는다. 이유를 적는다 | 받는 쪽 |

상태를 바꾸면 **문서 머리의 `- 상태:` 줄과 아래 색인 표를 같은 커밋에서** 고친다.
