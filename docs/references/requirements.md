### **2. 비기능적 요구사항**

| **ID** | **분류** | **요구사항 상세** | **목표 수치 / 구현 방식** | **관련 기능** |
| --- | --- | --- | --- | --- |
| **NFR-01** | 실시간성 | 라이브 영상 송출 지연을 낮게 유지하여 입찰 타이밍 왜곡 방지 | 송출 지연 3초 이내. LiveKit 기반 미디어 서버로 저지연 실시간 송출 구성 | LIVE-005 |
| **NFR-02** | 동시성 처리 | 경매 마감 직전 다수의 동시 입찰 요청에 대해 서버 수신 순서 기준으로 정합성 보장 | 동시 입찰 초당 50건 처리 시 낙찰 오류 0건(100회 테스트 기준). 경매 행에 비관적 락(`SELECT ... FOR UPDATE`)을 걸어 입찰을 서버 수신 순서로 직렬화하고, `(auction, price)` UNIQUE 인덱스로 이중 방어 | AUCT-003~005 |
| **NFR-03** | 보안 - 결제/포인트 | 포인트 충전·보류·해제·정산·환불 트랜잭션의 무결성 및 위변조 방지 | 관련 테스트 시나리오 100회 실행 기준 정합성 오류 0건. 포인트 계좌에 비관적 락을 걸고 `PointTransaction` 원장에 모든 상태 변경을 기록, 결제는 상태 필드(READY/DONE)로 idempotent 처리 | POINT-001~004, PAY-001, SETTLE-001 |
| **NFR-04** | 보안 - 개인정보 | 전신 사진·신체 정보, 사업자등록증 이미지, 계좌 정보 등 민감 정보는 접근 권한을 최소화하여 보관하고, 전신 사진은 사용자가 삭제하기 전까지 보관하되 삭제 요청 시 지체 없이 파기 | 삭제 요청 처리 24시간 이내 완료. 전신 사진·사업자등록증·계좌 정보는 비공개(private) 버킷에 저장하고 만료 시간이 있는 presigned URL로만 접근을 허용해 접근 권한을 최소화. 시착 프로필 사진은 삭제 요청 시 S3 객체와 DB 레코드를 즉시 삭제 처리(목표치보다 빠른 즉시 파기) | TRYON-001~002, BIZ-001, POINT-003 |
| **NFR-05** | 확장성 | 다수의 동시 시청자·채팅·입찰 트래픽에 대한 서버 확장 대응 | 동시 접속자 200명 기준 정상 서비스. EC2 인스턴스(4 vCPU / 15GiB RAM) 위에서 Docker Compose로 BE/AI/미디어 서버를 함께 운영 | LIVE-005, CHAT-001, AUCT-003 |
| **NFR-06** | 가용성 | 라이브 방송 및 경매 진행 중 서비스 중단 최소화 | 시연/테스트 라이브 세션 기준 서버 원인 방송 중단 0회(외부 요인 제외). 배포 파이프라인은 헬스체크를 통과하지 못하면 직전 이미지로 자동 롤백해 배포로 인한 서비스 중단을 최소화 | LIVE-002 |
| **NFR-07** | 응답 속도 | AI 옷 시착 이미지 생성 응답 시간에 대한 사용자 경험 기준 | 이미지 생성 5초 이내 응답. VLM 캡셔닝 → FLUX 참조 이미지 생성 → CatVTON 합성의 3단계 파이프라인을 노트북 GPU(6GB급) 환경에서 모델을 단계별로 순차 로드·해제하며 VRAM 한도 내에서 처리하도록 구성 | TRYON-003~004 |
| **NFR-08** | 사용성 | 모바일 환경에서의 라이브 시청/입찰 UX 최적화 | 모바일 뷰 주요 화면 로딩 2초 이내 | LIVE-005, AUCT-003 |
| **NFR-09** | 모니터링/로깅 | 입찰, 결제, 정산, 포인트 상태 변경 등 주요 이벤트에 대한 로그 기록 | 주요 이벤트 100건 테스트 기준 로그 누락 0건. 포인트는 `PointTransaction` 원장으로 모든 상태 변경 이력을 기록 | AUCT-007~008, POINT-002 |
| **NFR-10** | 호환성 | 주요 브라우저에서의 정상 동작 | Chrome/Safari 최신 버전 기준 정상 동작 | 전체 |
| **NFR-11** | 배치 처리 정확성 | 배송 완료 후 일정 기간 미확정 주문에 대한 자동 구매 확정 배치 처리 | 자동 확정 배치 100건 테스트 기준 오류 0건. `OrderAutoConfirmScheduler`가 10분 주기로 스캔하며, 배송완료(DELIVERED) 후 3일 경과 시 자동 확정 처리 | ORDER-003 |

📌 위 수치는 개발 초기 단계에서 잡아둔 목표치이며, 추후 부하 테스트(k6, Locust 등) 및 반복 테스트 시나리오를 통해 검증하고 조정한다.

### **3. 우선순위 및 MVP 범위**

기능별 상세 우선순위(필수/필수·프로토타입/추가/운영 정책/회의 필요)와 MVP 범위는 기능 정의서를 따른다. 본 문서의 비기능 요구사항은 기능 정의서의 **필수** 항목 구현과 함께 우선 반영한다.
